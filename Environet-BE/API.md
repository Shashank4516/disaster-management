# EnvironetBE — API Reference

Live reference for every implemented endpoint, with request examples and real
response payloads. For endpoints still on the roadmap, see
[ENDPOINTS.md](ENDPOINTS.md); anything listed in the *Not implemented yet*
section at the bottom does not exist yet.

**Base URL:** `http://localhost:3000` (Docker dev stack) — point at
`http://<host>:3000` otherwise.

## Conventions

- All requests and responses are JSON. Don't send `Content-Type` for GETs; send
  `Content-Type: application/json` on POSTs with a body.
- All timestamps are ISO 8601 UTC, e.g. `2026-09-12T11:44:42.966Z`.
- **Error shape** — every error is a JSON object with an `error` message:

  ```json
  { "error": "node not found" }
  ```

  | Status | Meaning |
  | --- | --- |
  | `400` | Bad query/body (e.g. unknown sensor name or range) |
  | `401` | Missing/invalid credentials (bad login, missing or expired bearer token) |
  | `404` | Unknown resource id |
  | `503` | Backend or database problem (check `/db/health`) |

- **Risk levels** — `0` NORMAL, `1` WATCH, `2` WARNING, `3` CRITICAL.
- **Alert severity** — mirrors the risk level that triggered it: `2` WARNING, `3` CRITICAL.
- **`source` field on readings/assessments** — `simulated` (generated by the
  built-in mock ingestion) or `real` (from physical nodes). Filter accordingly:
  operational views should query `WHERE source = 'real'`.
- **Auth** — protected endpoints expect `Authorization: Bearer <token>`; tokens
  come from `POST /api/auth/login` and expire after 12 hours.

## 1. Health

### `GET /health`

Process liveness — always `200` while the API is serving. Does **not** check the
database (use `/db/health` for that).

```bash
curl http://localhost:3000/health
```

```json
{
  "status": "ok",
  "uptime": 477.534031669,
  "timestamp": "2026-09-12T11:54:17.064Z"
}
```

### `GET /db/health`

Database connectivity + versions. `200` when reachable, `503` with the driver
error message when not (used by the container HEALTHCHECK).

```bash
curl http://localhost:3000/db/health
```

```json
{
  "status": "up",
  "pgVersion": "PostgreSQL 18.6 on x86_64-pc-linux-musl, compiled by gcc (Alpine 15.2.0) 15.2.0, 64-bit",
  "timescaledbVersion": "2.29.2",
  "latencyMs": 35
}
```

### `GET /api/nodes/:id/history?sensor=&range=`

Time series for one sensor on one node.

- `sensor` (required) — registry sensor name, one of:
  `flame`, `mq135_gas`, `soil_moisture`, `ultrasonic_water_level`, `rain_gauge`,
  `turbidity`, `bmp280_pressure`, `dht22_temp`, `dht22_humidity`
- `range` (required) —
  `1h` (1-minute buckets) · `6h` (5-minute) · `24h` (15-minute) → bucketed from
  raw rows, fully real-time · `7d` / `30d` → **hourly continuous aggregates**
  (pre-computed by TimescaleDB, includes the current partial hour)

```bash
curl "http://localhost:3000/api/nodes/W01/history?sensor=ultrasonic_water_level&range=1h"
```

```json
{
  "node_id": "W01",
  "sensor": "ultrasonic_water_level",
  "range": "1h",
  "bucket_source": "raw",
  "points": [
    { "bucket": "2026-09-12T10:54:00.000Z", "level_cm": 45.24, "rate_of_rise": 3, "samples": 9 },
    { "bucket": "2026-09-12T10:55:00.000Z", "level_cm": 45.50, "rate_of_rise": 0.25, "samples": 12 }
  ]
}
```

_(61 points for `1h`; array truncated here.)_ Point fields for short ranges are
the sensor's value columns averaged per bucket, plus `samples` (rows in bucket).

Long ranges return the hourly aggregate columns instead (note the `time` key):

```bash
curl "http://localhost:3000/api/nodes/W01/history?sensor=ultrasonic_water_level&range=7d"
```

```json
{
  "node_id": "W01",
  "sensor": "ultrasonic_water_level",
  "range": "7d",
  "bucket_source": "hourly_continuous_aggregate",
  "points": [
    { "time": "2026-09-11T12:00:00.000Z", "avg_level_cm": 45.42, "max_level_cm": 46.33, "avg_rate_of_rise": 1.16 },
    { "time": "2026-09-11T13:00:00.000Z", "avg_level_cm": 45.18, "max_level_cm": 46.53, "avg_rate_of_rise": 0.51 }
  ]
}
```

Per-sensor point fields for `7d`/`30d`:

| sensor | fields |
| --- | --- |
| `flame` | `any_detection`, `detection_count`, `samples` |
| `mq135_gas` | `avg_gas_ppm`, `max_gas_ppm`, `samples` |
| `soil_moisture` | `avg_moisture_pct`, `max_moisture_pct`, `samples` |
| `ultrasonic_water_level` | `avg_level_cm`, `max_level_cm`, `avg_rate_of_rise` |
| `rain_gauge` | `tip_count`, `rainfall_mm`, `max_rainfall_rate_mmph`, `samples` |
| `turbidity` | `avg_turbidity_ntu`, `max_turbidity_ntu`, `samples` |
| `bmp280_pressure` | `avg_pressure_hpa`, `max_pressure_hpa`, `samples` |
| `dht22_temp` | `avg_celsius`, `max_celsius`, `samples` |
| `dht22_humidity` | `avg_relative_humidity_pct`, `max_relative_humidity_pct`, `samples` |

**Errors:**

```json
{ "error": "unknown sensor \"bogus\"", "valid": ["flame", "mq135_gas", "…"] }
```

`400` unknown `sensor` or `range` (response includes the valid values) · `404`
unknown node · `503` database error.

### `GET /api/nodes/:id/config` 🔒

Threshold configuration for the node — what its risk evaluation runs against.
Requires auth. Returns engine defaults, this node's stored overrides, and the
merged effective values.

```bash
curl http://localhost:3000/api/nodes/W01/config -H "Authorization: Bearer <token>"
```

```json
{
  "node_id": "W01",
  "defaults": { "gas_ppm_warning": 40, "gas_ppm_critical": 90, "level_cm_warning": 75, "level_cm_critical": 90 },
  "overrides": { "level_cm_warning": 80 },
  "effective": { "gas_ppm_warning": 40, "gas_ppm_critical": 90, "level_cm_warning": 80, "level_cm_critical": 90 },
  "updated_at": "2026-09-12T12:40:10.220Z"
}
```

_(14 threshold keys in total — abbreviated here; see `defaults` in the response
for the full list.)_

**Errors:** `401` · `404` unknown node · `503`.

### `PUT /api/nodes/:id/config` 🔒

Upsert threshold overrides. Body: `{ "<threshold_key>": number, ... }`. Keys not
in the engine's threshold list are rejected (typos fail loudly); a PUT merges
into existing overrides, so only the sent keys change. Unknown keys → `400` with
the valid list. The one non-numeric key is `"predictive_escalation"` (boolean) —
it toggles the engine's predictive escalation for this node (see
[Analytics](#7-analytics)).

```bash
curl -X PUT http://localhost:3000/api/nodes/W01/config \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"level_cm_warning": 80, "temp_c_warning": 35}'
```

```json
{
  "node_id": "W01",
  "overrides": { "level_cm_warning": 80, "temp_c_warning": 35 },
  "effective": { "level_cm_warning": 80, "temp_c_warning": 35 },
  "updated_at": "2026-09-12T12:42:44.901Z"
}
```

The next risk-engine cycle (≤5s) evaluates against the new values.

**Errors:** `400` non-object body, unknown key, or non-numeric value · `401` ·
`404` unknown node · `503`.

## 3. Alerts

### `GET /api/alerts`

Alert list, newest first. All filters optional and combinable.

| Query param | Example | Description |
| --- | --- | --- |
| `severity` | `3` | Exact severity (2 WARNING, 3 CRITICAL) |
| `hazard_type` | `flood` | `fire` / `flood` / `air_quality` |
| `node_id` | `W01` | Node id |

| `from` / `to` | `2026-09-12T00:00:00Z` | ISO timestamps on `triggered_at` |

### `PATCH /api/alerts/:id/acknowledge` 🔒

Marks an active alert as acknowledged by the current user. Requires
`Authorization: Bearer <token>`. Body (optional): `{ "note": "string" }`.
Idempotent — re-acknowledging returns the alert unchanged. Appends an
`acknowledged` event to the alert's trail.

```bash
curl -X PATCH http://localhost:3000/api/alerts/65/acknowledge \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"note": "Team dispatched to site"}'
```

```json
{
  "alert": {
    "id": 65,
    "node_id": "W01",
    "node_name": "Water Node 1",
    "hazard_type": "flood",
    "severity": 3,
    "message": "flood risk level 3 on node W01 (factors: level_cm=44.88, rate_of_rise=0, rainfall_rate_mmph=0)",
    "triggered_at": "2026-09-12T11:47:09.538Z",
    "resolved_at": null,
    "status": "acknowledged",
    "acknowledged_by": 1,
    "acknowledged_at": "2026-09-12T12:43:32.411Z"
  }
}
```

**Errors:** `401` no/invalid token · `404` unknown alert · `409` resolved
alerts cannot be acknowledged.

### `PATCH /api/alerts/:id/resolve` 🔒

Marks an alert as resolved (from `active` or `acknowledged`). Optional
`{ "note": "resolution note" }`. Idempotent. Appends a `resolved` event.

```bash
curl -X PATCH http://localhost:3000/api/alerts/65/resolve \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"note": "Water level back to normal"}'
```

Returns the same shape as acknowledge, with `status: "resolved"` and
`resolved_at` set.

**Errors:** `401` · `404` · `503`.

### `PATCH /api/alerts/:id/escalate` 🔒

Raises severity by one (WARNING 2 → CRITICAL 3), capped at 3. Optional
`{ "note": "…" }`; defaults to `severity 2 → 3`. Appends an `escalated` event.

```bash
curl -X PATCH http://localhost:3000/api/alerts/65/escalate \
  -H "Authorization: Bearer <token>"
```

Returns the updated alert. **Errors:** `401` · `404` · `409` when already at
maximum severity or resolved.

## 5. Users (admin only)

### `GET /api/users` 🔒

Lists operator accounts. Requires an **admin** role token.

```bash
curl http://localhost:3000/api/users -H "Authorization: Bearer <token>"
```

```json
{
  "users": [
    { "id": 1, "username": "admin", "role": "admin", "created_at": "2026-09-12T11:44:40.120Z" }
  ],
  "count": 1
}
```

### `POST /api/users` 🔒

Creates an account. Body: `{ "username": string, "password": string (min 8),
"role"?: "admin"|"authority"|"viewer" }` (role defaults to `authority`).

```bash
curl -X POST http://localhost:3000/api/users \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"username":"site_lead","password":"password123","role":"authority"}'
```

```json
{ "user": { "id": 2, "username": "site_lead", "role": "authority", "created_at": "2026-09-12T12:43:56.569Z" } }
```

**Errors:** `400` invalid username/password/role · `401` · `403` non-admin ·
`409` username taken.

### `DELETE /api/users/:id` 🔒

Deletes an account. Refused (`409`) for your own account, and for accounts that
have acknowledged alerts or authored alert events (preserves the audit trail —
deactivate such accounts by other means).

```bash
curl -X DELETE http://localhost:3000/api/users/2 -H "Authorization: Bearer <token>"
```

```json
{ "status": "deleted" }
```

**Errors:** `400` invalid id · `401` · `403` non-admin · `404` unknown user ·
`409` self-deletion or alert history present.

## 6. Risk engine

### `POST /risk/evaluate`

Runs one evaluation of every active node immediately (the ingestion loop already
calls this after every 5-second cycle). Writes `risk_assessments` rows and
creates deduplicated alerts when a hazard is at WARNING/CRITICAL (no active or
acknowledged alert for the same node+hazard within the past hour).

```bash
curl -X POST http://localhost:3000/risk/evaluate
```

```json
{ "status": "ok", "assessed": 4, "alertsCreated": 0 }
```

`assessed` = hazard assessments written (2 per node), `alertsCreated` = new
alerts from this evaluation. Thresholds per node can be tuned through the
`node_configs` table (see the README's risk-engine section for the demo recipe).

## 7. Analytics

### `GET /api/analytics/forecast?node=&hazard=&horizon=` 🔒

Heuristic short-horizon forecast (`linear-trend-v1`): a least-squares linear
trend over the last 24h of hourly aggregates for the hazard's driving metric,
projected forward. Requires auth. Params: `node` (id, required), `hazard`
(`fire` | `flood` | `air_quality`, required), `horizon` (1–6 hours, default 3).

The driving metric per hazard: flood → `level_cm`, fire → `gas_ppm`,
air_quality → `gas_ppm` (forest nodes) or `turbidity_ntu` (water nodes).

```bash
curl "http://localhost:3000/api/analytics/forecast?node=W01&hazard=flood&horizon=3" \
  -H "Authorization: Bearer <token>"
```

```json
{
  "node_id": "W01",
  "hazard": "flood",
  "metric": "level_cm",
  "method": "linear-trend-v1",
  "available": true,
  "history_hours": 24,
  "current_risk_level": 0,
  "trend": { "slope_per_hour": -0.015, "r2": 0.25, "samples": 24 },
  "predictive_escalation_enabled": false,
  "points": [
    { "horizon_hours": 1, "time": "2026-09-12T14:24:46.234Z", "predicted_value": 45.24, "predicted_risk_level": 0, "confidence": 0.58 },
    { "horizon_hours": 2, "time": "2026-09-12T15:24:46.235Z", "predicted_value": 45.22, "predicted_risk_level": 0, "confidence": 0.51 },
    { "horizon_hours": 3, "time": "2026-09-12T16:24:46.235Z", "predicted_value": 45.21, "predicted_risk_level": 0, "confidence": 0.44 }
  ]
}
```

- `predicted_risk_level` = the risk the node's own thresholds would assign to
  the predicted value. `confidence` decays ~7% per hour out, scaled by the fit's
  R².
- When the node has fewer than 6 hourly samples, `available` is `false` with a
  `reason` instead of `points`.

**Predictive escalation** — when a node's config enables it (see below), the
risk engine runs this same forecast after every ingestion cycle and lifts the
assessed level **before** any threshold is crossed: a predicted WARNING within
6h raises NORMAL → `1` (WATCH); a predicted CRITICAL raises it to `2`
(WARNING). Real crossings still produce the full level. The prediction is
recorded in `contributing_factors` (`predicted_metric`, `predicted_value`,
`predicted_in_hours`, `predicted_level`). Toggle per node:

```bash
curl -X PUT http://localhost:3000/api/nodes/W01/config \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"predictive_escalation": true}'
```

**Errors:** `400` unknown hazard or horizon out of range · `401` · `404`
unknown node · `503`.

### WebSocket events (`ws://<host>:3000/ws`)

Live push channel. Events are JSON frames: `{ "event": "<name>", "payload": {…} }`.

| Event | Fired when | Payload |
| --- | --- | --- |
| `reading` | Every sensor reading ingested (simulator ticks ~every 5s, or a node push) | `{ node_id, sensor, time, values }` — `sensor` is the registry name (e.g. `ultrasonic_water_level`), `values` are that sensor's value columns |
| `alert` | A new alert is triggered by the risk engine | The full alert object (`id`, `node_id`, `hazard_type`, `severity`, `message`, `triggered_at`, `status`, …) |
| `node_status` | A node's online/offline state flips | `{ node_id, online, battery_pct?, signal_dbm?, time }` |

Client → server messages:

```json
{ "type": "subscribe", "node_ids": ["F01"] }   // receive only these nodes' events
{ "type": "unsubscribe" }                        // back to everything
```

No auth on the socket (public read data). The server pings every 30s and drops
dead connections — respond to pings (browsers do this automatically).

Quick check from a terminal:

```bash
npx wscat -c ws://localhost:3000/ws
```

## 8. Ingestion (write path for nodes)

### `POST /api/ingest` (API key required)

The write path real sensor nodes use when MQTT is unavailable, plus the tool
for manual tests and backfills. Authentication is **per node** with the API key
issued at registration (see `POST /api/nodes`) — send it as an `X-API-Key`
header. A node can only write readings for itself, and each reading is
attributed to that node's active sensor instance (calibration record)
automatically.

Accepts a single reading or a batch (up to 100). Batch inserts are
all-or-nothing: one invalid entry rejects the whole request with `400`.

| Field | Required | Notes |
| --- | --- | --- |
| `sensor` | ✔ | Registry name (e.g. `ultrasonic_water_level`) — selects the target table |
| `values` | ✔ | Object with that sensor's value columns (at least one); `detected` (flame) must be boolean, others numeric |
| `node_id` | — | Must equal the authenticated node (validated) |
| `time` | — | ISO 8601; defaults to now |
| `source` | — | `real` (default) or `simulated` |
| `quality_flag` | — | `-1` fault, `0` suspect, `1` valid (default) |
| `sensor_instance_id` | — | Override automatic calibration attribution |
| `readings` | — | Array form: `{ "readings": [ …up to 100 of the above… ] }` |

Duplicate `(time, node_id)` rows are upserted (retried transmissions overwrite,
never duplicate).

```bash
curl -X POST http://localhost:3000/api/ingest \
  -H "X-API-Key: <node-api-key>" -H "Content-Type: application/json" \
  -d '{"sensor":"ultrasonic_water_level","values":{"level_cm": 51.2, "raw_distance_cm": 68.8}}'
```

```json
{ "ack": true, "accepted": 1 }
```

Batch form:

```bash
curl -X POST http://localhost:3000/api/ingest \
  -H "X-API-Key: <node-api-key>" -H "Content-Type: application/json" \
  -d '{"readings":[{"sensor":"ultrasonic_water_level","values":{"level_cm": 51.3}},{"sensor":"dht22_temp","values":{"celsius": 25.1}}]}'
```

**Errors:** `400` invalid entry or cross-node write · `401` missing/unknown key ·
`503` database error.
